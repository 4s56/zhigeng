# 文件整理

## 铁律
- **先看再动**：`list_files` 看清结构，要改内容先 `read_file`。
- **不删原件**：删除只在用户明确说了「删」之后做，且先说明删什么，一次删一组就报告一组。
- **不留垃圾**：批量操作产生的临时文件（.tmp、.bak、排序用的中间文件）收尾时清掉。
- 一次整理只解决一个目标，不要顺手把无关目录也重排了。

## 流程

1. **摸清现状** —— 列出目录，按「项目 / 素材 / 文档 / 临时」四类在心里分好，把判断说给用户看。
2. **给方案再动手** —— 用 3-5 行说清打算怎么分、哪些会改名、哪些不动。用户点头再执行。
3. **小步执行** —— 每次最多处理一个子目录，做完报一句「已整理 X，动了 N 个文件」。
4. **收尾** —— 给一张整理后的树状图（最多三层），并指出还没处理的部分。

## 命名约定
- 中文名优先，单词之间用空格或短横线，不用下划线堆叠。
- 日期统一 `2026-11-12`，不混用 `20261112` / `11.12`。
- 同一项目的文件放同一目录，入口文件叫 `index.html` / `README.md`。
